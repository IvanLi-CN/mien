# Snailfish 路线图

## 1. 推进原则

路线图按可验证的退出标准推进，不以日历日期作为完成条件。每个里程碑必须先建立可运行的纵向切片，再扩展平台和边界；安全、指纹一致性和失败恢复是横切门槛，不放到最后补做。

首个发布的目标是 macOS Apple Silicon 桌面与 Docker `linux/amd64` 服务端。Windows/Linux 桌面、原生 ARM64 容器、多用户和云同步属于后续范围。

## 2. 里程碑

### M0：契约与可行性

**目标**：确认技术路线在真实环境中可行，冻结实现契约。

交付物：

- 产品需求、架构、详细设计、技术选型、ADRs、主题规格、测试计划与安全威胁模型。
- fingerprint-chromium 148 能力清单基线：逐项验证文档化开关是否生效。
- macOS ARM64 内核启动 spike：有头启动、CDP 探针、进程退出与数据目录。
- Docker 沙箱 spike：在目标基础镜像中验证非 root + 用户命名空间沙箱是否可用；记录不可用时的配置。
- Docker 显示 spike：Xvfb + openbox + Chromium 有头启动，确认窗口尺寸与 `screen.*` 行为。
- 协议引擎 spike：sing-box mixed 入站、VLESS/VMess/Shadowsocks/Trojan 受控节点、分享链接解析、远程 DNS、失败关闭。
- GPL 法律评审：sing-box 独立进程分发、源码要约、名称使用限制与发布物合规。
- 指纹探针 v0：采集 UA、UA-CH、时区、语言、WebGL、canvas、音频、字体、WebRTC 候选。

退出标准：

- 两个平台都能启动 148 内核并加载一个本地探针页。
- 沙箱结论明确：严格模式可用，或明确记录必须采用的容器配置与残余风险。
- 协议引擎在 spike 中可启动、可访问受控节点，远程 DNS 与失败关闭可验证。
- GPL 合规结论明确；不接受时确定 Xray-core 回退方案。
- 能力清单中不包含未经验证的开关。

### M1：核心骨架与 macOS 有头运行

**目标**：建立可保存档案并启动浏览器的最小纵向切片。

交付物：

- Rust workspace、核心库、桌面宿主和基础 Web UI。
- SQLite schema、迁移、档案 CRUD、分组与标签。
- 内核注册表：148 安装、SHA-256 校验、能力清单加载。
- 指纹规格 v1 与确定性 argv 构建器。
- 协议引擎注册表与基础代理：sing-box 校验、配置生成、mixed 入站、HTTP/SOCKS/VLESS 受控节点。
- macOS 有头启动、状态事件、正常停止、日志文件。
- 主密钥存入钥匙串，代理配置与凭据字段加密。

退出标准：

- 在 macOS 上创建档案、配置代理、启动有头浏览器、访问探针页并停止。
- 相同规格重复启动生成相同 argv；不同档案数据目录隔离。
- 内核或引擎校验失败、引擎启动失败均能阻止启动并给出稳定错误码。

### M2：指纹一致性与网络防护

**目标**：让指纹规格、种子和代理行为达到可测试的一致性。

交付物：

- 指纹种子生成、冲突检测、一致性校验、能力清单校验。
- 主机对齐预设与跨系统画像确认流程。
- `--disable-spoofing` 映射、WebRTC 默认策略、DoH 与 IPv6 防护。
- 协议矩阵：VLESS、VMess、Shadowsocks、Trojan；Hysteria2/TUIC/WireGuard 按能力清单验证。
- 分享链接导入、类型化配置、引擎配置生命周期（0600、check、启动后删除）。
- 远程 DNS、失败关闭、代理检查、出口 IP（配置回显端点时）、错误分类与事件。
- 指纹探针完整版与 golden fixture；同一档案三次启动一致性测试。
- 运行时对账、崩溃退避、并发准入、日志轮转与脱敏。

退出标准：

- 同一档案三次启动的显式与派生指纹一致；不同档案种子与派生特征不同。
- DNS canary 无目标泄漏；WebRTC 无直连候选；引擎停止或节点断开后网络失败关闭。
- 强杀内核与控制面重启后状态可对账，无重复运行时。
- 10 个档案并发启动在目标资源内成功。

### M3：服务化与 Docker 有头/无头

**目标**：交付可远程使用的 Web 控制面与容器运行形态。

交付物：

- 服务端宿主：登录、会话、API Token、CSRF、限流、错误结构、分页、幂等。
- WebSocket 事件流、健康检查、审计事件。
- 服务端 Web UI：档案、指纹、代理配置与分享链接导入、运行时、日志、内核、协议引擎、Token 管理。
- Docker 镜像：非 root、Xvfb、openbox、可选 noVNC、sing-box、数据卷、健康检查；记录 Hysteria2/TUIC 的 UDP 出站要求。
- 有头模式与无头模式切换，降低保证标记。
- 导入导出、加密导出、备份恢复说明。
- OpenAPI 文档与 API 集成测试，覆盖代理 CRUD、分享链接导入、检查和脱敏视图。

退出标准：

- Docker 中完成登录、创建档案、Xvfb 有头启动、查看器（可选）和停止。
- 无头档案可启动且 UI/API 标记降低保证。
- 容器重启后数据保留、状态对账、无孤儿进程。
- 未认证、越权、CSRF、超限请求均被拒绝。

### M4：加固与发布

**目标**：达到可发布的安全、质量与分发标准。

交付物：

- 内核准入测试套件与 148 基线报告；协议引擎准入与 Tier A 矩阵报告。
- 完整指纹、代理协议、生命周期、安全和性能测试报告。
- macOS 签名、公证、DMG、自动更新清单。
- Docker 镜像漏洞扫描、SBOM、BSD-3-Clause 与 GPL-3.0 许可清单、源码要约、发布标签。
- 已知限制、部署指南、故障排查和可接受使用政策。
- 发布回滚与安全响应流程。

退出标准：

- PRD 的 PRD-ACC-001 至 PRD-ACC-010 全部通过，或有书面残余风险接受。
- 无未关闭的高危安全问题。
- 发布说明列出内核缺陷、协议矩阵、节点 bootstrap 泄漏、无头限制、跨系统画像限制、显示与字体限制。
- 冷启动、启动/停止耗时、并发与 24 小时浸泡达到目标。

## 3. 横切工作流

| 工作流 | 负责内容 | 介入点 |
| --- | --- | --- |
| 指纹质量 | 探针、golden fixture、一致性阈值、内核差异报告 | M0 起持续 |
| 安全 | 威胁模型、沙箱、密钥、认证、依赖与镜像扫描 | M0 起持续 |
| 可靠性 | 状态机、对账、崩溃恢复、浸泡测试 | M1 起持续 |
| 文档 | 部署、限制、故障排查、API、可接受使用 | 每个里程碑更新 |
| 发布工程 | 构建、签名、公证、镜像、SBOM、回滚 | M3 起 |

## 4. 依赖与顺序

- M0 的沙箱与显示结论决定 M3/Docker 的默认配置，必须先于服务化实现完成。
- 能力清单与指纹探针必须先于 UI 指纹编辑器冻结，否则 UI 会暴露无效字段。
- 协议引擎的远程 DNS、失败关闭与协议矩阵必须在发布前通过受控节点和 canary 测试，不能仅靠代码审查。
- sing-box 的 GPL 合规与法律评审必须在 M0 给出结论，否则 M2 的协议矩阵无法进入发布路径。
- macOS 签名与公证需要稳定的应用标识和发布证书，应在 M3 前准备。
- 内核 148 的安全问题跟踪是持续工作；若上游修复或新版本达到准入标准，按 ADR-0002 走迁移。

## 5. 完成定义

一个里程碑只有在以下条件同时满足时才算完成：

- 交付物已合并到主线，文档与契约同步。
- 覆盖该里程碑的自动化测试在目标平台通过。
- 新增或变更的安全边界有威胁模型条目和验证证据。
- 已知限制写入 UI、API 或发布文档，不以口头约定代替。
- 没有未处理的高危缺陷或未声明的功能降级。
