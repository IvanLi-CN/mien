# Mien 路线图

## 1. 推进原则

路线图按可验证的退出标准推进，不以日历日期作为完成条件。每个里程碑必须先建立可运行的纵向切片，再扩展平台和边界；安全、指纹一致性和失败恢复是横切门槛，不放到最后补做。

首个发布的目标是 macOS Apple Silicon 桌面与 Docker `linux/amd64` 服务端。Windows/Linux 桌面、原生 ARM64 容器、多用户和云同步属于后续范围。

## 2. 里程碑

### M0：契约与可行性

**目标**：确认技术路线在真实环境中可行，冻结实现契约。

交付物：

- 产品需求、架构、详细设计、技术选型、ADRs、主题规格、测试计划与安全威胁模型。
- Deep Current 视觉系统、Profiles 首屏 comp 与 1440/1024/768/390 的响应式规则。
- fingerprint-chromium 148 能力清单基线：逐项验证文档化开关是否生效，包括 `headless_chrome_ua_patch`。
- macOS ARM64 内核启动 spike：有头启动、CDP 探针、进程退出与数据目录。
- Docker 沙箱 spike：在目标基础镜像中验证非 root + 用户命名空间沙箱是否可用；记录不可用时的配置。
- Docker 显示 spike：Xvfb + openbox + Chromium 有头启动，确认窗口尺寸与 `screen.*` 行为。
- 协议引擎 spike：Xray-core 动态 Add/Remove Inbound、Outbound、Rule，单实例共享出站、连接复用、VLESS/VMess/Shadowsocks/Trojan 受控节点、分享链接解析、远程 DNS、失败关闭。
- MPL-2.0 合规评审：Xray-core 独立进程分发、许可证与来源信息、发布物合规。
- 契约冻结：OpenAPI、事件 schema、错误码、数据库 schema、Xray 映射、内核/引擎清单、UI surface 与测试 fixture 目录一次性冻结，并接入 CI 校验（OpenAPI 生成差异、schema 编译、DDL 执行、`$ref` 解析、链接检查与 `spec_contract_check`）。
- 指纹探针 v0：采集 UA、UA-CH、时区、语言、WebGL、canvas、音频、字体、WebRTC 候选。

退出标准：

- 两个平台都能启动 148 内核并加载一个本地探针页。
- 沙箱结论明确：严格模式可用，或明确记录必须采用的容器配置与残余风险。
- Xray 单实例可动态增删入站/出站/规则，相同 key 的档案复用连接，远程 DNS 与失败关闭可验证。
- TUIC 退出 v1；Hysteria2 在锁定 Xray 版本上的支持结论明确。
- MPL-2.0 合规结论明确。
- 契约冻结完成：上述契约在 CI 中通过校验，冻结后任何变更必须同步 SPEC、测试与文档。
- 能力清单中不包含未经验证的开关。

### M1：核心骨架与 macOS 有头运行

**目标**：建立可保存档案并启动浏览器的最小纵向切片。

交付物：

- Rust workspace、核心库、桌面宿主和基础 Web UI。
- SQLite schema、迁移、档案 CRUD、分组与标签。
- 内核注册表：148 安装、SHA-256 校验、能力清单加载。
- 指纹规格 v1 与确定性 argv 构建器。
- 协议引擎注册表与共享引擎：Xray 校验、动态出站、每运行档案 HTTP 入站、路由规则、共享出站引用计数、VLESS 受控节点。
- macOS 有头、无头、伪有头启动，状态事件、正常停止、日志文件。
- 主密钥存入钥匙串，代理配置与凭据字段加密。

退出标准：

- 在 macOS 上创建档案、配置代理、启动有头浏览器、访问探针页并停止。
- 相同规格重复启动生成相同 argv；不同档案数据目录隔离。
- 内核或引擎校验失败、引擎启动失败均能阻止启动并给出稳定错误码。

### M2：指纹一致性与网络防护

**目标**：让指纹规格、种子和代理行为达到可测试的一致性。

交付物：

- 指纹种子生成（密码学安全随机源）、显式字段复制时重新生成种子、一致性校验、能力清单校验。
- 主机对齐预设与跨系统画像确认流程。
- `--disable-spoofing` 映射、WebRTC 默认策略、DoH 与 IPv6 防护。
- 协议矩阵：VLESS、VMess、Shadowsocks、Trojan；Hysteria2/WireGuard 按能力清单验证；TUIC 后续。
- 分享链接导入、类型化配置、动态入站/出站/路由、引用计数、连接复用与引擎崩溃重建。
- 运行模式矩阵与能力门禁：伪有头只在 `headless_chrome_ua_patch=true` 时可用，UI/API 返回 UA 范围与降低保证。
- 远程 DNS、失败关闭、代理检查、出口 IP（配置回显端点时）、错误分类与事件。
- 指纹探针完整版与 golden fixture；同一档案三次启动一致性测试。
- 运行时对账、崩溃退避、并发准入、日志轮转与脱敏。

退出标准：

- 同一档案三次启动的显式与派生指纹一致；不同档案种子与派生特征不同。
- DNS canary 无目标泄漏；WebRTC 无直连候选；共享引擎故障时代理档案失败关闭，活且可归属内核经有界重建后按原端口恢复，直连不受影响。
- 强杀内核与控制面重启后状态可对账，无重复运行时。
- 10 个档案并发启动在目标资源内成功。

### M3：服务化与 Docker 有头/无头

**目标**：交付可远程使用的 Web 控制面与容器运行形态。

交付物：

- 服务端宿主：登录、会话、API Token、CSRF、限流、错误结构、分页、幂等。
- WebSocket 事件流、健康检查、审计事件。
- 服务端 Web UI：档案、指纹、代理配置与分享链接导入、运行时、日志、内核、协议引擎、Token 管理。
- Docker 镜像：非 root、Xvfb、openbox、可选 noVNC、Xray-core、数据卷、健康检查；记录 Hysteria2 的 UDP 出站要求。
- 有头、无头与伪有头模式切换，降低保证标记与 UA 范围说明。
- 导入导出、加密导出、备份恢复说明。
- OpenAPI 文档与 API 集成测试，覆盖代理 CRUD、分享链接导入、检查和脱敏视图。

退出标准：

- Docker 中完成登录、创建档案、Xvfb 有头启动、查看器（可选）和停止。
- 无头档案可启动且 UI/API 标记降低保证。
- 容器重启后数据保留、状态对账、无孤儿进程。
- 未认证、越权、CSRF、超限请求均被拒绝。

### M4：加固与发布

**目标**：达到可发布的安全、质量与分发标准。

交付物：

- 内核准入测试套件与 148 基线报告；协议引擎准入与 Tier A 矩阵报告。
- 完整指纹、代理协议、生命周期、安全和性能测试报告。
- macOS AdHoc 签名、DMG、SHA-256、artifact attestation、Tauri 自动更新清单。
- 手动 `release_target`、draft reservation、同 identity recovery 和 GitHub Release 发布记录。
- Docker 镜像漏洞扫描、SBOM、BSD-3-Clause 与 MPL-2.0 许可清单、来源信息、发布标签。
- Docker 可复现构建证据：CI 从同一 `source_sha` 连续构建两次并比对镜像 digest。
- 项目许可证落地：仓库根 `LICENSE`（Apache-2.0）、`README` 许可链接、`NOTICE`、`LICENSES/` 与 SBOM 随每个发布物分发。
- 已知限制、部署指南、故障排查和可接受使用政策。
- 发布回滚与安全响应流程。

退出标准：

- PRD 的 PRD-ACC-001 至 PRD-ACC-010 全部通过；P0 为 0，P1 的泄漏、回退、路径穿越、崩溃循环、运行时重复或孤儿、沙箱未披露类别为 0，不得整类豁免；其余 P1 只能逐项具名限期接受。
- 无未关闭的高危安全问题。
- Docker 两次构建的镜像 digest 相等；项目 `LICENSE`（Apache-2.0）与第三方许可清单随发布物分发，许可扫描无未处置项。
- 发布说明列出内核缺陷、协议矩阵、节点 bootstrap 泄漏、无头限制、跨系统画像限制、显示与字体限制。
- 冷启动、启动/停止耗时、并发与 24 小时浸泡达到目标。

## 3. 横切工作流

| 工作流 | 负责内容 | 介入点 |
| --- | --- | --- |
| 指纹质量 | 探针、golden fixture、一致性阈值、内核差异报告 | M0 起持续 |
| 安全 | 威胁模型、沙箱、密钥、认证、依赖与镜像扫描 | M0 起持续 |
| 可靠性 | 状态机、对账、崩溃恢复、浸泡测试 | M1 起持续 |
| 文档 | 部署、限制、故障排查、API、可接受使用 | 每个里程碑更新 |
| 发布工程 | GitHub Actions、AdHoc 打包、镜像、SBOM、回滚 | M3 起 |

## 4. 依赖与顺序

- M0 的沙箱与显示结论决定 M3/Docker 的默认配置，必须先于服务化实现完成。
- 能力清单与指纹探针必须先于 UI 指纹编辑器冻结，否则 UI 会暴露无效字段。
- 协议引擎的远程 DNS、失败关闭与协议矩阵必须在发布前通过受控节点和 canary 测试，不能仅靠代码审查。
- Xray-core 的 MPL-2.0 合规、单实例 API 安全、连接复用和共享故障域必须在 M0 给出结论，否则 M2 的协议矩阵无法进入发布路径。
- AdHoc 不依赖 Apple 证书；仍需在 M3 前准备 Tauri 更新签名密钥、release environment、draft reservation 策略、tag 保护和一次性手动放行说明。
- 内核 148 的安全问题跟踪是持续工作；若上游修复或新版本达到准入标准，按 ADR-0002 走迁移。

## 5. 完成定义

一个里程碑只有在以下条件同时满足时才算完成：

- 交付物已合并到主线，文档与契约同步。
- 覆盖该里程碑的自动化测试在目标平台通过。
- 新增或变更的安全边界有威胁模型条目和验证证据。
- 已知限制写入 UI、API 或发布文档，不以口头约定代替。
- 没有未处理的高危缺陷或未声明的功能降级。
