# Evidence

`run.log` is generated by `run.sh` from a Linux/amd64 Agent VM execution. Logs should contain only sanitized runtime output. Missing evidence is a blocked result; do not infer a pass from the intended configuration.

`t32-m3-gap-acceptance.log.md` is recovered from the agent session transcript after the host logs were deleted during T32 cleanup. It states in its own header which outputs are lost and which are byte-verbatim, and it must not be read as a complete log.

`reproducibility.log` records the GitHub Actions two-builder OCI digest comparison for `Dockerfile.repro-probe`, with the run id and both digests. It is a Markdown record, not raw command output, and it is not evidence that `Dockerfile.server` is reproducible: the probe image has no Chromium or Xray assets.
