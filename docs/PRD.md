# Mien 产品需求文档

## 1. 文档目的

本文定义 Mien 首个可用版本的产品边界、用户价值、功能与非功能要求、验收门槛和已知限制，作为架构、主题规格、测试计划和发布评审的共同输入。本文描述“做什么”和“做到什么程度”，不规定具体代码结构；实现契约由 `docs/specs/` 下的主题规格维护。

## 2. 背景与问题

多账号运营、跨地区产品测试、广告投放验证、隐私研究和自动化 QA 都需要在同一台机器上维护多个彼此隔离的浏览器环境。普通浏览器配置文件只能隔离 Cookie 与缓存，无法稳定隔离或控制 User-Agent、Client Hints、时区、语言、Canvas、音频、WebGL、字体和 WebRTC 等指纹面；手工拼接启动参数既容易产生内部矛盾，也无法在团队和服务器之间复现。

fingerprint-chromium 提供了成熟的指纹伪装内核，但它只解决“浏览器内如何伪装”，不解决环境档案管理、指纹一致性、正向代理协议与认证、进程监督、远程运行、团队访问和升级治理。Mien 的产品价值在于把这些能力组织成一个可长期维护的运行平台，并诚实标注内核与宿主环境无法覆盖的边界。

## 3. 产品定位

Mien 是本地优先、可服务化部署的指纹浏览器环境管理平台。它管理多个隔离档案，为每个档案生成一致、可复现的指纹规格，绑定独立代理，监督浏览器进程，并通过桌面应用或 Web 控制面提供操作入口。

产品定位不是“匿名工具”，也不是“风控绕过服务”。它提供环境隔离、指纹一致性和自动化接口，不承诺隐藏用户身份、规避平台检测或绕过任何服务条款。

## 4. 目标用户与非目标

### 4.1 目标用户

| 用户 | 典型任务 | 关键诉求 |
| --- | --- | --- |
| 多账号运营人员 | 管理店铺、社媒或广告账户环境 | 档案隔离、指纹稳定、代理不泄漏、操作简单 |
| QA 与兼容性工程师 | 在多个地区、语言和平台画像下验证产品 | 可复现环境、批量启动、自动化接口、测试证据 |
| 隐私与反追踪研究者 | 观察站点在不同指纹下的行为 | 指纹面可控、结果可重复、限制透明 |
| 自动化开发者 | 用脚本驱动多个独立浏览器环境 | 稳定 API、CDP 入口、进程与代理生命周期可控 |
| 小型团队运维 | 在服务器上集中运行浏览器环境 | Docker 部署、Web 访问、数据持久化、可观测性 |

### 4.2 非目标用户与场景

- 需要完全匿名、抗取证或隐藏真实网络身份的用户。
- 需要批量注册、欺诈、垃圾信息、绕过支付风控或其他违法用途的用户。
- 需要内置代理销售、短信接码、验证码打码或账号交易的用户。
- 需要移动端浏览器或 Android/iOS 设备农场的用户。

本文使用 [`GLOSSARY.md`](GLOSSARY.md) 中的定义。关键术语包括环境档案、指纹规格、种子、指纹内核、能力清单、代理网关、协议引擎、有头模式、无头模式、主机对齐和降低保证。

## 6. 目标与成功指标

### 6.1 产品目标

1. 用户可以在 macOS 桌面或 Docker 服务中，以不超过十分钟完成首次部署并启动第一个隔离档案。
2. 每个档案的指纹在相同内核、相同规格和相同启动参数下可重复；不同档案之间不共享种子和浏览器数据。
3. 代理流量失败关闭，默认不产生 DNS、WebRTC 或 IPv6 直连泄漏。
4. 正向代理覆盖 VLESS、VMess、Shadowsocks、Trojan、Hysteria2 等主流协议，通过单实例共享 Xray 引擎与每运行档案入站/路由隔离浏览器网络，并复用相同节点与凭据的上游连接。
5. 控制面、运行时、内核与协议引擎升级彼此解耦，升级不会静默改变已有档案的指纹。
6. 所有已知限制在 UI、API 与文档中显式呈现，不以“不可检测”作为卖点。

### 6.2 成功指标

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 首次部署到首个档案启动 | 中位数不超过 10 分钟 | 引导流程埋点或人工计时 |
| 档案首次启动成功率 | 不低于 95% | 运行时事件统计 |
| 非预期崩溃率 | 不高于 2% 的启动次数 | 运行时退出码与崩溃日志 |
| 指纹探针一致性通过率 | 同档案同规格 100%；跨档案差异率不低于 95% | 自动化探针矩阵 |
| 代理泄漏用例通过率 | 100% | DNS、WebRTC、IPv6、失败关闭测试 |
| Tier A 代理协议矩阵 | VLESS、VMess、Shadowsocks、Trojan 全部通过 | 受控节点端到端测试 |
| 10 个档案并发启动 | 8 vCPU / 16 GB 环境下全部成功 | 容量测试 |
| 有头模式启动耗时 | p95 不超过 5 秒（内核已预热） | 运行时指标 |
| 停止后孤儿进程 | 0 | 生命周期浸泡测试 |

## 7. 范围

### 7.1 首个发布必须包含

- macOS Apple Silicon 桌面应用与 Docker `linux/amd64` 服务端两种运行形态。
- 环境档案的创建、编辑、复制、归档、删除、分组、标签、搜索。
- 指纹规格编辑、预设、种子生成、一致性校验和启动参数生成。
- 每个档案独立的浏览器数据目录、代理配置和运行状态。
- 有头模式：macOS 宿主桌面；Docker 内 Xvfb + openbox，可选 noVNC 查看。
- 无头模式：macOS 与 Docker 均支持，但明确标记为降低保证。
- 伪有头模式：无头运行，仅将 `HeadlessChrome` UA 改为 `Chrome`；其他 Headless 特征保留，标记为降低保证。
| 正向代理协议引擎：单实例共享 Xray-core；HTTP/HTTPS/SOCKS5、VLESS、VMess、Shadowsocks、Trojan、Hysteria2；WireGuard 作为 Tier B 按清单支持；每运行档案独立回环入站与路由；相同节点/凭据共享出站与连接池；单条分享链接导入；远程 DNS、失败关闭、凭据不进入浏览器。
- 档案启动、停止、崩溃检测、日志、进程监督、并发准入和重启对账。
- 服务端 Web UI、登录、API Token、REST/WebSocket 控制面和自动化启动入口。
- 档案导入导出、加密导出、数据备份与恢复说明。
- 内核与协议引擎安装、校验、版本绑定和能力清单校验。
- 安全基线：密钥保护、凭据脱敏、路径校验、CSRF、登录限流、内核校验和、沙箱状态检查。
- 中英文界面，以及独立于界面语言的档案语言配置。
- 已知限制提示：宿主绑定显示属性、字体枚举、跨系统画像、无头/伪有头模式、CDP 暴露面。

### 7.2 后续版本

- Windows 与 Linux 桌面应用。
- 原生 `linux/arm64` 内核与服务镜像。
- 团队空间、多用户、角色权限和审计检索。
- 云端同步、跨设备档案迁移和托管备份。
- 定时任务、批量操作、RPA 模板和脚本市场。
- 订阅 URL 导入、定时刷新、节点测速与多节点调度。
- WireGuard 的更多传输组合与深度稳定性基准；v1 仅按能力清单提供配置与导入。TUIC 在 Xray 支持后重新评估。
- 每档案独立虚拟显示分辨率。
- 内核补丁分支与自建安全构建流水线。
- 地理位置、屏幕分辨率、字体白名单等内核尚不支持的字段。

### 7.3 明确不做

- 内置代理、住宅 IP、短信或验证码服务。
- 账号密码托管、自动登录、支付或交易自动化。
- 承诺通过 CreepJS、PixelScan、Cloudflare 或任何第三方检测。
- 承诺匿名性、抗取证或隐藏真实身份。
- 修改上游内核以绕过第三方平台限制。
- Windows 7、32 位系统、移动端浏览器。
- 多租户 SaaS 计费与运营后台。

## 8. 用户场景

### 8.1 首次启动 macOS 档案

用户从 GitHub Release 下载 DMG，先校验 SHA-256 或 artifact attestation，再按发布说明手动放行 AdHoc 应用；首次打开时应用解压内置内核并校验校验和，创建主密钥并存入钥匙串。用户新建档案，选择“macOS 主机对齐”预设，系统生成种子、语言、时区、CPU 核心数和窗口尺寸。用户配置代理并测试连接，点击启动，浏览器窗口打开，控制面显示运行状态、调试端口和代理延迟。

### 8.2 Docker 服务端集中运行

运维使用数据卷启动 Mien 容器，首次启动生成管理员密码并写入受保护文件。运维通过浏览器登录 Web UI，创建档案并配置代理。默认有头模式在 Xvfb 中启动浏览器，需要人工查看时开启一次性 noVNC 会话；自动化任务通过 API Token 启动档案并获取本机 CDP 地址。容器重启后，控制面恢复到停止状态，不遗留僵尸进程。

### 8.3 指纹一致性验证

测试人员创建两个档案，使用同一套预设但不同种子，分别启动并通过探针采集 UA、Client Hints、时区、语言、Canvas、音频、WebGL、字体和 WebRTC 候选。相同档案重复启动得到相同派生特征；不同档案的种子派生特征不同；代理出口 IP 与配置一致；无直连 DNS 或 UDP 泄漏。

### 8.4 无头自动化

开发者在 Docker 中以无头模式启动档案，通过 API 获取 CDP WebSocket 地址，使用 Playwright 连接。控制面在档案卡片和 API 响应中标记“降低保证”，并提示无头特征可能与有头模式不同。开发者可以选择切换到 Xvfb 有头模式重新验证；如果只需要不在 UA 中暴露 `HeadlessChrome`，可以显式选择“伪有头”，但其他 Headless 特征仍保留。

### 8.5 内核升级评估

新内核发布后，维护者导入候选内核，运行内核准入测试。控制面显示能力清单差异、已知缺陷和受影响的档案。已有档案默认继续使用原内核；用户显式迁移后，系统重新校验指纹规格并提示派生特征可能变化。升级过程中不静默替换运行中档案的内核。

## 9. 功能需求

### 9.1 档案管理

| 编号 | 需求 |
| --- | --- |
| PRD-FR-001 | 用户可以创建、编辑、复制、归档和删除环境档案；档案包含名称、分组、标签、备注、指纹规格、代理、运行偏好和启动地址。名称可重复，档案标识必须唯一且不可变。 |
| PRD-FR-002 | 用户可以按名称、分组、标签、档案状态（active/archived/deleted）和运行状态筛选与搜索档案；核心返回分页结果，桌面端通过 Tauri IPC 使用同一分页契约，不依赖远程服务端。 |
| PRD-FR-003 | 复制档案时默认生成新的种子和新的浏览器数据目录；用户可以复制指纹配置、代理配置和启动偏好，但不能默认复制运行中的会话。 |
| PRD-FR-004 | 删除档案必须二次确认；删除后浏览器数据目录进入可恢复的回收状态或按配置立即清除，不允许留下可被其他档案复用的残留目录。 |
| PRD-FR-005 | 每个档案使用独立的数据目录；不同档案不得共享 Cookie、缓存、LocalStorage、IndexedDB、Service Worker 或下载目录。 |
| PRD-FR-006 | 档案元数据变更必须持久化到 SQLite，并通过事务保证分组、标签和档案本体的一致性。 |

### 9.2 指纹规格

| 编号 | 需求 |
| --- | --- |
| PRD-FR-007 | 用户可以配置种子、操作系统、操作系统版本、浏览器品牌、品牌版本、CPU 核心数、语言列表、时区、窗口尺寸、伪装开关和 WebRTC 策略。 |
| PRD-FR-008 | 系统必须生成非零的 32 位随机种子，并检测与现有档案的种子冲突；种子生成使用密码学安全随机源。 |
| PRD-FR-009 | 系统必须提供主机对齐预设：macOS 宿主默认 macOS 画像，Docker 默认 Linux 画像。Windows 宿主预设只在 Windows 桌面版本发布后生效；跨系统画像必须显式选择并显示降低保证提示。 |
| PRD-FR-010 | 系统必须校验画像内部一致性，包括平台与 UA、UA-CH 平台版本、品牌与品牌版本、CPU 核心数、语言与时区、代理地区与语言时区建议；不可能组合必须拒绝保存或启动。 |
| PRD-FR-011 | 相同内核版本、相同种子和相同启动参数必须产生相同的派生特征；系统不得在启动时引入额外随机源改变指纹。 |
| PRD-FR-012 | 系统只能暴露当前内核能力清单声明的开关和取值；不得把内核接受但无效果的参数作为功能展示。能力清单之外的字段必须拒绝。 |
| PRD-FR-013 | 指纹规格必须带 schema 版本；升级时保留未知字段或拒绝加载，不得静默丢弃用户配置。迁移必须可回滚或提供导出备份。 |
| PRD-FR-014 | 系统必须把指纹规格确定性地转换为参数数组，不经过 shell 拼接；参数顺序和取值在相同规格下稳定。 |
| PRD-FR-015 | 系统必须在 UI 与 API 中说明屏幕尺寸、设备像素比、颜色深度和字体枚举受宿主环境限制，不能承诺任意伪造。 |

### 9.3 代理与网络

| 编号 | 需求 |
| --- | --- |
| PRD-FR-016 | 每个档案可以绑定一个正向代理，支持 HTTP、HTTPS、SOCKS5，以及 VLESS、VMess、Shadowsocks（AEAD/2022，插件按能力清单）、Trojan；Hysteria2、WireGuard 作为 Tier B 按协议引擎能力清单支持；TUIC 在后续版本评估。也可以选择直连，但直连必须显示风险提示。 |
| PRD-FR-017 | 代理凭据（HTTP/SOCKS 用户名密码、VLESS UUID、VMess 用户 ID、Shadowsocks/Trojan/Hysteria2 密码、私钥）不得出现在内核命令行、日志、事件流或 API 响应中；凭据必须加密存储，编辑时只显示是否已设置。 |
| PRD-FR-018 | 系统必须通过单实例共享的 Xray-core 协议引擎处理代理协议、认证、TLS/REALITY/WS/gRPC/QUIC 与出站 DNS；每个运行档案拥有独立的回环 HTTP 入站和路由规则；Chromium 只看到无认证的回环代理入口；产品不得自行实现协议，也不得把凭据交给内核。 |
| PRD-FR-019 | 系统必须默认通过代理远程解析目标域名；只有代理节点主机名允许本地 bootstrap 解析；目标域名的 DNS 查询不得本地泄漏。 |
| PRD-FR-020 | 系统必须默认阻止非代理 UDP，WebRTC 不得产生直连候选；禁用该保护需要高级确认并记录审计动作 `proxy.non_proxied_udp.disable`。Hysteria2 的 QUIC 只用于引擎到节点，不改变浏览器非代理 UDP 策略。 |
| PRD-FR-021 | 协议引擎不可用、配置无效、认证失败或节点不可达时，档案必须失败关闭，不得回退直连或其他代理；浏览器应表现为网络不可用。 |
| PRD-FR-022 | 系统必须通过协议引擎执行代理检查，返回协议握手、认证、延迟、出口 IP（配置回显端点时）和可选的地区信息；检查失败不阻止用户保存配置，但启动前必须显示状态。 |
| PRD-FR-023 | 系统必须通过指纹规格 `network.doh_mode=disabled`、`network.ipv6_mode=block` 和能力清单声明的控制处理 IPv6 与 DNS-over-HTTPS 绕过风险；启动探针验证生效值，无法保证时阻止启动或显示明确限制。 |
| PRD-FR-065 | 每个宿主必须运行且只运行一个受监督的共享协议引擎；档案启停、代理变更和路由变更不得重启整个引擎，也不得为每个档案启动独立引擎进程。 |
| PRD-FR-066 | 相同节点、凭据、传输、TLS/REALITY 与 mux 配置的运行档案必须共享出站与可复用连接；共享出站必须引用计数，最后一个使用档案停止后才删除。 |
| PRD-FR-067 | 共享引擎故障必须使所有运行档案失败关闭并产生全局事件；引擎重启后必须按原入站端口重建运行档案配置，重建失败时受影响运行时标记失败，不得直连回退。 |

#### 9.3.1 协议矩阵

| 协议 | 首发级别 | 首发要求 | 说明 |
| --- | --- | --- | --- |
| HTTP / HTTPS | 基础 | 支持用户名密码与远程 DNS | 由协议引擎统一处理 |
| SOCKS5 | 基础 | 支持用户名密码与域名地址 | 由协议引擎统一处理 |
| VLESS | Tier A | TCP、TLS、REALITY、WS、gRPC | UUID、flow、TLS/REALITY 参数 |
| VMess | Tier A | TCP、WS、gRPC、AEAD | 用户 ID、加密选型、传输 |
| Shadowsocks | Tier A | AEAD、2022、按能力清单的插件 | 方法、密码、插件参数 |
| Trojan | Tier A | TLS、WS | 密码、TLS、传输 |
| Hysteria2 | Tier B | QUIC、TLS、混淆 | 需要容器允许 UDP 出站 |
| TUIC | 后续 | QUIC | Xray 当前不支持；不进入 v1 |
| WireGuard | Tier B | UDP | 按引擎清单与独立测试 |

Tier A 参与发布门禁；Tier B 必须明确标注能力与失败原因，不得静默降级为其他协议或直连。

### 9.4 运行时

| 编号 | 需求 |
| --- | --- |
| PRD-FR-024 | 用户可以启动和停止档案；启动必须幂等，同一档案同一时间只能有一个受监督运行时。 |
| PRD-FR-025 | 运行时必须经历明确的 starting、running、stopping、stopped、crashed、failed 状态，并通过事件流推送给 UI。 |
| PRD-FR-026 | 系统必须检测内核或共享协议引擎退出、记录退出码和最近日志；内核崩溃执行有界退避；共享引擎崩溃影响所有运行档案，必须失败关闭、发布全局事件、按有界退避重启并重建运行配置，不得回退直连或其他代理。 |
| PRD-FR-027 | 停止档案时必须先请求内核正常退出，等待数据落盘；超过超时后才强制终止进程组；随后删除该档案的路由规则和入站，并按引用计数释放共享出站；共享引擎本身不因单个档案停止而退出。 |
| PRD-FR-028 | 控制面或容器重启后，系统必须对账已有进程与状态文件；无法确认归属的进程不得被误认为当前运行时，遗留进程必须被安全清理或标记。 |
| PRD-FR-029 | 系统必须限制并发运行档案数，并在启动前检查可用内存、内核与协议引擎文件完整性；容量评估必须计入共享引擎、每档案入站/路由和连接复用，而不是每档案一个引擎。 |
| PRD-FR-030 | 运行时与协议引擎日志必须结构化、可轮转、可脱敏，并按档案保留最近一段时间的启动、退出和错误信息。 |
| PRD-FR-031 | 系统可以为运行中的档案暴露本机 CDP 调试地址；默认只绑定回环地址，不得默认暴露到容器外或局域网。 |

## 11. 约束与依赖

| 约束 | 影响 |
| --- | --- |
| 内核固定为 fingerprint-chromium `148.0.7778.215` | 上游 150 在 canvas 伪装下存在渲染崩溃与站点加载失败；150 没有 macOS 构建；148 源码已公开。 |
| 上游不提供技术支持 | 缺陷只能通过版本准入、沙箱、功能降级或自建补丁分支处理。 |
| 上游源码延迟发布 | 新版本在源码公开前无法审计，不能作为安全敏感升级的默认选择。 |
| macOS 构建仅 ARM64 | 不支持 Intel Mac；Apple Silicon 是唯一 macOS 目标。 |
| Linux 构建仅 x86_64 | Docker 镜像为 `linux/amd64`；原生 ARM64 需自行编译内核。 |
| Chromium 不支持代理认证与高级协议 | 必须由单实例共享 Xray 引擎处理；每个运行档案使用回环 HTTP 入站与路由；内核不接触上游凭据。 |
| 协议引擎为 MPL-2.0 | Xray-core 作为独立进程分发，保留许可证与来源信息；不修改二进制；发布物合规检查仍是发布门槛。 |
| 协议矩阵受引擎版本约束 | VLESS、VMess、Shadowsocks、Trojan 为首发必过；Hysteria2、WireGuard 按能力清单和独立测试标注；TUIC 不进入 v1。 |
| 代理节点主机名可能需要 bootstrap 解析 | 可能暴露节点域名；目标域名不得本地解析，限制必须在 UI 与安全文档中说明。 |
| 显示属性不可任意伪造 | `screen.*`、`devicePixelRatio`、`colorDepth` 与窗口外框受宿主或 Xvfb 配置约束。 |
| 字体枚举受宿主字体集影响 | 跨系统画像可能泄漏宿主字体；主机对齐是默认策略。 |
| 无头与伪有头模式指纹保证较弱 | 作为显式降级选项，不作为默认运行模式；伪有头只覆盖 UA，其他 Headless 特征仍在。 |
| CDP 没有认证 | 只能绑定回环地址；远程自动化需通过隧道或额外网关。 |
| Chromium 沙箱在容器中需要额外配置 | 默认要求验证沙箱状态；无沙箱运行必须显式授权并记录风险。 |
| 内核为 BSD-3-Clause | 分发时必须保留版权与许可声明，并链接上游源码。 |

## 12. 验收与发布门槛

### 12.1 必过场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| PRD-ACC-001 | macOS 首次部署 | 安装、内核校验、创建档案、启动有头浏览器、访问探针页、停止并再次启动成功。 |
| PRD-ACC-002 | Docker 首次部署 | 非 root 容器启动、登录、创建档案、Xvfb 有头启动、Web UI 状态正确、数据卷重启后保留。 |
| PRD-ACC-003 | 指纹一致性 | 同一档案三次启动的探针哈希一致；不同档案的种子派生特征不同；平台、UA、UA-CH、语言、时区内部一致。 |
| PRD-ACC-004 | 代理与泄漏 | HTTP/SOCKS5 认证代理与 VLESS、VMess、Shadowsocks、Trojan 节点可用；Hysteria2 按矩阵验证；分享链接可导入；DNS 无目标泄漏；WebRTC 无直连候选；共享引擎停止或节点断开后所有运行档案失败关闭；相同出站 key 的档案复用连接；IPv6 无绕过。 |
| PRD-ACC-005 | 无头降级 | 无头与伪有头档案可启动并被标记降低保证；UI 与 API 均显示限制；伪有头只改变 UA，其他 Headless 特征仍被记录；切换到有头模式后可重新验证。 |
| PRD-ACC-006 | 生命周期与恢复 | 100 次启动/停止无孤儿；运行档案可动态增删而不重启共享引擎；强杀共享引擎后所有运行档案失败关闭，重启后按原端口重建；控制面重启后状态对账正确。 |
| PRD-ACC-007 | 导入导出 | 明文与加密导出可导入；错误 schema、超长字段、路径穿越和非法代理被拒绝；默认导出不含代理凭据；加密导出可完整恢复代理配置。 |
| PRD-ACC-008 | 安全基线 | 未登录不能写操作；错误密码限流；Token 可撤销；代理凭据为密文；内核与协议引擎校验失败拒绝启动；容器非 root；Xray 管理 API 只绑定回环；沙箱状态可确认，无法确认时拒绝启动，显式无沙箱有审计；日志与 API 无秘密。 |
| PRD-ACC-009 | 容量与性能 | 10 个档案并发运行；启动与停止满足性能目标；24 小时浸泡通过。 |
| PRD-ACC-010 | 发布物 | macOS 应用、嵌套内核、Xray-core 与 frameworks 为 AdHoc 签名，`codesign --verify --deep --strict` 通过且 `Signature=adhoc`；不公证，Gatekeeper 首次启动被阻止且有经校验的手动放行说明；Docker 镜像可复现构建、带健康检查、通过漏洞扫描；内核的 BSD-3-Clause 与 Xray-core 的 MPL-2.0 许可、来源信息和已知限制文档齐全。 |

### 12.2 发布门槛

- PRD-ACC-001 至 PRD-ACC-010 全部通过，或经产品负责人书面接受残余风险。
- 已知内核缺陷、无头限制、跨系统画像限制和宿主显示限制必须在发布说明中列出。
- 不得以关闭泄漏保护或关闭沙箱作为默认配置来通过验收。
- VLESS、VMess、Shadowsocks、Trojan 的受控节点测试必须通过；Hysteria2 的失败必须记录为已知限制，不能静默降级。
- 内核的 BSD-3-Clause、Xray-core 的 MPL-2.0 许可、来源信息和发布物合规检查必须完成；TUIC 不得作为 v1 能力宣传。
- 任何未关闭的高危安全问题阻断发布。

## 13. 风险与缓解

| 风险 | 证据 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 内核 150 在 canvas 读回时崩溃 | 上游 issue #94、#95、#104、#112：`getImageData`/`readPixels` 触发 SIGSEGV，x.com 加载失败，148 正常 | 高 | 固定 148；150 仅作为候选内核，必须通过准入测试后才可升级。 |
| 内核 148 存在 WebGL readPixels 越界访问报告 | 上游 issue #102：打包 16 位格式被按 RGBA8888 处理，渲染进程可触发堆越界读写 | 高 | 强制 Chromium 沙箱；容器禁止默认 `--no-sandbox`；限制不可信站点；跟踪上游修复并保留补丁分支预案。 |
| 字体与屏幕属性无法按画像伪造 | 上游 issue #105：屏幕与字体开关无效果；宿主字体仍可枚举 | 高 | 默认主机对齐；UI 显式提示；测试矩阵覆盖；不承诺跨系统字体一致。 |
| 无头模式暴露 Headless 特征 | 上游 README 仅声明替换 UA 中的 HeadlessChrome | 中 | 无头作为降级选项；默认 Xvfb 有头；伪有头只声明 UA 范围；文档和 API 标记。 |
| Docker 中 Chromium 沙箱配置困难 | 容器默认 seccomp/用户命名空间限制 | 高 | 提供受支持的 seccomp/启动配置；启动前验证沙箱状态；无沙箱必须显式开关并记录。 |
| Apple Silicon 运行 amd64 镜像性能下降 | 无原生 linux/arm64 内核 | 中 | 文档说明模拟运行；容量目标按 amd64 环境测量；原生 ARM64 作为后续项。 |
| 上游无技术支持且源码延迟 | 上游 README 明确说明 | 中 | 固定版本、能力清单、准入测试、保留回滚；不依赖最新版本。 |
| CreepJS 在 148 Windows 上卡住 | 上游 issue #108 | 中 | 使用自有探针为主、第三方站点为辅；不以单一站点作为发布门禁。 |
| 指纹噪声实现存在一致性问题 | 上游 issue #98、#99：子区域读回与完整读回不一致 | 中 | 探针覆盖子区域与完整读回；记录已知差异；不作为“完美一致”承诺。 |
| `navigator.deviceMemory` 返回 16/32 不常见 | 上游 issue #100 | 低 | 能力清单标注；探针记录；后续内核修复后重新评估。 |
| CDP 输入事件坐标可被检测 | 上游 issue #110 | 中 | 仅作为自动化接口；不承诺反检测；文档说明。 |
| 共享引擎是网络单点 | 一个 Xray 进程承载所有运行档案；引擎崩溃或 API 不可用会同时影响全部档案 | 高 | 失败关闭；有界重启；按原入站端口重建；全局事件；容量与故障注入测试。 |
| 协议引擎供应链或 MPL 合规问题 | Xray-core 为 MPL-2.0；二进制可能被篡改 | 高 | 固定版本与 SHA-256；独立进程；保留许可证与来源信息；发布前合规检查。 |
| 分享链接或代理配置注入 | 外部输入包含协议参数、路径和超大字段 | 高 | 类型化 schema、字段白名单、大小限制、不联网解析、不执行代码；引擎配置由产品生成而非直接透传。 |
| 共享引擎崩溃或节点不可达 | 引擎是所有运行档案的网络单点 | 高 | 引擎先于内核就绪；失败关闭；不使用直连回退；记录全局事件与稳定错误码；有界重启并重建；提供诊断。 |
| 代理节点主机名 bootstrap 泄漏 | 本地解析节点域名是连接前置条件 | 中 | 只解析节点主机名，不解析目标域名；UI 与安全文档说明；支持 IP 节点避免解析。 |
| Hysteria2 的 QUIC 在容器网络受限 | 容器或宿主可能阻止 UDP 出站 | 中 | 能力清单标注；Docker 部署文档说明 UDP 要求；失败时明确报错，不回退其他协议。 |
| 多账号使用触碰平台条款 | 产品性质 | 高 | 可接受使用政策；用户责任；不提供规避指导。 |
| 代理凭据或 Cookie 泄露 | 本地或容器被入侵 | 高 | 主密钥保护、文件权限、日志脱敏、卷加密建议、最小权限。 |
| 容器逃逸或宿主内核漏洞 | 非 root、沙箱、依赖漏洞 | 高 | 非 root、只读根文件系统、丢弃能力、seccomp、镜像扫描、及时更新。 |

## 14. 合规与可接受使用

Mien 仅用于合法、授权的环境隔离、测试、隐私研究和多账号运营。用户必须遵守目标网站的服务条款、当地法律、数据保护要求和代理服务商条款。

禁止将产品用于欺诈、身份盗用、未经授权的访问、垃圾信息、规避执法、支付欺诈、未成年人伤害或其他违法活动。产品不提供代理、账号、验证码或身份材料，也不对用户使用产品造成的账号封禁、数据损失或法律责任负责。

产品文档和 UI 不得暗示产品可以隐藏真实身份或保证绕过检测。发现滥用或安全漏洞时，维护者可以限制分发、发布安全公告或终止支持。
