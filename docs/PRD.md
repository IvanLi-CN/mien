# Snailfish 产品需求文档

## 1. 文档目的

本文定义 Snailfish 首个可用版本的产品边界、用户价值、功能与非功能要求、验收门槛和已知限制，作为架构、主题规格、测试计划和发布评审的共同输入。本文描述“做什么”和“做到什么程度”，不规定具体代码结构；实现契约由 `docs/specs/` 下的主题规格维护。

## 2. 背景与问题

多账号运营、跨地区产品测试、广告投放验证、隐私研究和自动化 QA 都需要在同一台机器上维护多个彼此隔离的浏览器环境。普通浏览器配置文件只能隔离 Cookie 与缓存，无法稳定隔离或控制 User-Agent、Client Hints、时区、语言、Canvas、音频、WebGL、字体和 WebRTC 等指纹面；手工拼接启动参数既容易产生内部矛盾，也无法在团队和服务器之间复现。

fingerprint-chromium 提供了成熟的指纹伪装内核，但它只解决“浏览器内如何伪装”，不解决环境档案管理、指纹一致性、代理认证、进程监督、远程运行、团队访问和升级治理。Snailfish 的产品价值在于把这些能力组织成一个可长期维护的运行平台，并诚实标注内核与宿主环境无法覆盖的边界。

## 3. 产品定位

Snailfish 是本地优先、可服务化部署的指纹浏览器环境管理平台。它管理多个隔离档案，为每个档案生成一致、可复现的指纹规格，绑定独立代理，监督浏览器进程，并通过桌面应用或 Web 控制面提供操作入口。

产品定位不是“匿名工具”，也不是“风控绕过服务”。它提供环境隔离、指纹一致性和自动化接口，不承诺隐藏用户身份、规避平台检测或绕过任何服务条款。

## 4. 目标用户与非目标

### 4.1 目标用户

| 用户 | 典型任务 | 关键诉求 |
| --- | --- | --- |
| 多账号运营人员 | 管理店铺、社媒或广告账户环境 | 档案隔离、指纹稳定、代理不泄漏、操作简单 |
| QA 与兼容性工程师 | 在多个地区、语言和平台画像下验证产品 | 可复现环境、批量启动、自动化接口、测试证据 |
| 隐私与反追踪研究者 | 观察站点在不同指纹下的行为 | 指纹面可控、结果可重复、限制透明 |
| 自动化开发者 | 用脚本驱动多个独立浏览器环境 | 稳定 API、CDP 入口、进程与代理生命周期可控 |
| 小型团队运维 | 在服务器上集中运行浏览器环境 | Docker 部署、Web 访问、数据持久化、可观测性 |

### 4.2 非目标用户与场景

- 需要完全匿名、抗取证或隐藏真实网络身份的用户。
- 需要批量注册、欺诈、垃圾信息、绕过支付风控或其他违法用途的用户。
- 需要内置代理销售、短信接码、验证码打码或账号交易的用户。
- 需要移动端浏览器或 Android/iOS 设备农场的用户。

## 6. 目标与成功指标

### 6.1 产品目标

1. 用户可以在 macOS 桌面或 Docker 服务中，以不超过十分钟完成首次部署并启动第一个隔离档案。
2. 每个档案的指纹在相同内核、相同规格和相同启动参数下可重复；不同档案之间不共享种子和浏览器数据。
3. 代理流量失败关闭，默认不产生 DNS、WebRTC 或 IPv6 直连泄漏。
4. 控制面、运行时和内核升级彼此解耦，升级不会静默改变已有档案的指纹。
5. 所有已知限制在 UI、API 与文档中显式呈现，不以“不可检测”作为卖点。

### 6.2 成功指标

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 首次部署到首个档案启动 | 中位数不超过 10 分钟 | 引导流程埋点或人工计时 |
| 档案首次启动成功率 | 不低于 95% | 运行时事件统计 |
| 非预期崩溃率 | 不高于 2% 的启动次数 | 运行时退出码与崩溃日志 |
| 指纹探针一致性通过率 | 不低于 95% 的受测档案 | 自动化探针矩阵 |
| 代理泄漏用例通过率 | 100% | DNS、WebRTC、IPv6、失败关闭测试 |
| 10 个档案并发启动 | 8 vCPU / 16 GB 环境下全部成功 | 容量测试 |
| 有头模式启动耗时 | p95 不超过 5 秒（内核已预热） | 运行时指标 |
| 停止后孤儿进程 | 0 | 生命周期浸泡测试 |

## 7. 范围

### 7.1 首个发布必须包含

- macOS Apple Silicon 桌面应用与 Docker `linux/amd64` 服务端两种运行形态。
- 环境档案的创建、编辑、复制、归档、删除、分组、标签、搜索。
- 指纹规格编辑、预设、种子生成、一致性校验和启动参数生成。
- 每个档案独立的浏览器数据目录、代理配置和运行状态。
- 有头模式：macOS 宿主桌面；Docker 内 Xvfb + openbox，可选 noVNC 查看。
- 无头模式：macOS 与 Docker 均支持，但明确标记为降低保证。
- 本地代理中继：HTTP/HTTPS/SOCKS5 上游、认证注入、远程 DNS、失败关闭。
- 档案启动、停止、崩溃检测、日志、进程监督、并发准入和重启对账。
- 服务端 Web UI、登录、API Token、REST/WebSocket 控制面和自动化启动入口。
- 档案导入导出、加密导出、数据备份与恢复说明。
- 内核安装、校验、版本绑定和能力清单校验。
- 安全基线：密钥保护、凭据脱敏、路径校验、CSRF、登录限流、内核校验和、沙箱状态检查。
- 中英文界面，以及独立于界面语言的档案语言配置。
- 已知限制提示：宿主绑定显示属性、字体枚举、跨系统画像、无头模式、CDP 暴露面。

### 7.2 后续版本

- Windows 与 Linux 桌面应用。
- 原生 `linux/arm64` 内核与服务镜像。
- 团队空间、多用户、角色权限和审计检索。
- 云端同步、跨设备档案迁移和托管备份。
- 定时任务、批量操作、RPA 模板和脚本市场。
- 每档案独立虚拟显示分辨率。
- 内核补丁分支与自建安全构建流水线。
- 地理位置、屏幕分辨率、字体白名单等内核尚不支持的字段。

### 7.3 明确不做

- 内置代理、住宅 IP、短信或验证码服务。
- 账号密码托管、自动登录、支付或交易自动化。
- 承诺通过 CreepJS、PixelScan、Cloudflare 或任何第三方检测。
- 承诺匿名性、抗取证或隐藏真实身份。
- 修改上游内核以绕过第三方平台限制。
- Windows 7、32 位系统、移动端浏览器。
- 多租户 SaaS 计费与运营后台。

## 8. 用户场景

### 8.1 首次启动 macOS 档案

用户安装签名应用，首次打开时应用解压内置内核并校验校验和，创建主密钥并存入钥匙串。用户新建档案，选择“macOS 主机对齐”预设，系统生成种子、语言、时区、CPU 核心数和窗口尺寸。用户配置代理并测试连接，点击启动，浏览器窗口打开，控制面显示运行状态、调试端口和代理延迟。

### 8.2 Docker 服务端集中运行

运维使用数据卷启动 Snailfish 容器，首次启动生成管理员密码并写入受保护文件。运维通过浏览器登录 Web UI，创建档案并配置代理。默认有头模式在 Xvfb 中启动浏览器，需要人工查看时开启一次性 noVNC 会话；自动化任务通过 API Token 启动档案并获取本机 CDP 地址。容器重启后，控制面恢复到停止状态，不遗留僵尸进程。

### 8.3 指纹一致性验证

测试人员创建两个档案，使用同一套预设但不同种子，分别启动并通过探针采集 UA、Client Hints、时区、语言、Canvas、音频、WebGL、字体和 WebRTC 候选。相同档案重复启动得到相同派生特征；不同档案的种子派生特征不同；代理出口 IP 与配置一致；无直连 DNS 或 UDP 泄漏。

### 8.4 无头自动化

开发者在 Docker 中以无头模式启动档案，通过 API 获取 CDP WebSocket 地址，使用 Playwright 连接。控制面在档案卡片和 API 响应中标记“降低保证”，并提示无头特征可能与有头模式不同。开发者可以选择切换到 Xvfb 有头模式重新验证。

### 8.5 内核升级评估

新内核发布后，维护者导入候选内核，运行内核准入测试。控制面显示能力清单差异、已知缺陷和受影响的档案。已有档案默认继续使用原内核；用户显式迁移后，系统重新校验指纹规格并提示派生特征可能变化。升级过程中不静默替换运行中档案的内核。

## 9. 功能需求

### 9.1 档案管理

| 编号 | 需求 |
| --- | --- |
| PRD-FR-001 | 用户可以创建、编辑、复制、归档和删除环境档案；档案包含名称、分组、标签、备注、指纹规格、代理、运行偏好和启动地址。名称可重复，档案标识必须唯一且不可变。 |
| PRD-FR-002 | 用户可以按名称、分组、标签和运行状态筛选与搜索档案；服务端返回分页结果，桌面端可以本地缓存但以服务端数据为准。 |
| PRD-FR-003 | 复制档案时默认生成新的种子和新的浏览器数据目录；用户可以复制指纹配置、代理配置和启动偏好，但不能默认复制运行中的会话。 |
| PRD-FR-004 | 删除档案必须二次确认；删除后浏览器数据目录进入可恢复的回收状态或按配置立即清除，不允许留下可被其他档案复用的残留目录。 |
| PRD-FR-005 | 每个档案使用独立的数据目录；不同档案不得共享 Cookie、缓存、LocalStorage、IndexedDB、Service Worker 或下载目录。 |
| PRD-FR-006 | 档案元数据变更必须持久化到 SQLite，并通过事务保证分组、标签和档案本体的一致性。 |

### 9.2 指纹规格

| 编号 | 需求 |
| --- | --- |
| PRD-FR-007 | 用户可以配置种子、操作系统、操作系统版本、浏览器品牌、品牌版本、CPU 核心数、语言列表、时区、窗口尺寸、伪装开关和 WebRTC 策略。 |
| PRD-FR-008 | 系统必须生成非零的 32 位随机种子，并检测与现有档案的种子冲突；种子生成使用密码学安全随机源。 |
| PRD-FR-009 | 系统必须提供主机对齐预设：macOS 宿主默认 macOS 画像，Docker 默认 Linux 画像，Windows 宿主默认 Windows 画像。跨系统画像必须显式选择并显示降低保证提示。 |
| PRD-FR-010 | 系统必须校验画像内部一致性，包括平台与 UA、UA-CH 平台版本、品牌与品牌版本、CPU 核心数、语言与时区、代理地区与语言时区建议；不可能组合必须拒绝保存或启动。 |
| PRD-FR-011 | 相同内核版本、相同种子和相同启动参数必须产生相同的派生特征；系统不得在启动时引入额外随机源改变指纹。 |
| PRD-FR-012 | 系统只能暴露当前内核能力清单声明的开关和取值；不得把内核接受但无效果的参数作为功能展示。能力清单之外的字段必须拒绝。 |
| PRD-FR-013 | 指纹规格必须带 schema 版本；升级时保留未知字段或拒绝加载，不得静默丢弃用户配置。迁移必须可回滚或提供导出备份。 |
| PRD-FR-014 | 系统必须把指纹规格确定性地转换为参数数组，不经过 shell 拼接；参数顺序和取值在相同规格下稳定。 |
| PRD-FR-015 | 系统必须在 UI 与 API 中说明屏幕尺寸、设备像素比、颜色深度和字体枚举受宿主环境限制，不能承诺任意伪造。 |

### 9.3 代理与网络

| 编号 | 需求 |
| --- | --- |
| PRD-FR-016 | 每个档案可以绑定一个 HTTP、HTTPS 或 SOCKS5 上游代理，支持用户名密码；也可以选择直连，但直连必须显示风险提示。 |
| PRD-FR-017 | 代理密码不得出现在内核命令行、日志、事件流或 API 响应中；密码必须加密存储，编辑时只显示是否已设置。 |
| PRD-FR-018 | 系统必须通过本地中继向内核提供无认证的代理地址，由中继向上游注入凭据；内核不得直接接触上游凭据。 |
| PRD-FR-019 | 系统必须默认使用远程 DNS，避免本机解析目标域名；DNS 查询不得绕过代理。 |
| PRD-FR-020 | 系统必须默认阻止非代理 UDP，WebRTC 不得产生直连候选；禁用该保护需要高级确认并记录审计事件。 |
| PRD-FR-021 | 代理中继不可用时，档案必须失败关闭，不得回退直连；浏览器应表现为网络不可用。 |
| PRD-FR-022 | 系统必须提供代理连通性检查，返回成功/失败、延迟、出口 IP 和可选的地区信息；检查失败不阻止用户保存配置，但启动前必须显示状态。 |
| PRD-FR-023 | 系统必须处理 IPv6 与 DNS-over-HTTPS 绕过风险；无法保证时必须在 UI 中显示限制，而不是静默忽略。 |

### 9.4 运行时

| 编号 | 需求 |
| --- | --- |
| PRD-FR-024 | 用户可以启动和停止档案；启动必须幂等，同一档案同一时间只能有一个受监督运行时。 |
| PRD-FR-025 | 运行时必须经历明确的 starting、running、stopping、stopped、crashed 状态，并通过事件流推送给 UI。 |
| PRD-FR-026 | 系统必须检测内核退出、记录退出码和最近日志、执行崩溃退避，并避免无限重启。 |
| PRD-FR-027 | 停止时必须先请求内核正常退出，等待数据落盘；超过超时后才强制终止进程组，并清理中继和调试端口。 |
| PRD-FR-028 | 控制面或容器重启后，系统必须对账已有进程与状态文件；无法确认归属的进程不得被误认为当前运行时，遗留进程必须被安全清理或标记。 |
| PRD-FR-029 | 系统必须限制并发运行档案数，并在启动前检查可用内存与内核文件完整性；资源不足时拒绝启动并给出可操作提示。 |
| PRD-FR-030 | 运行时日志必须结构化、可轮转、可脱敏，并按档案保留最近一段时间的启动、退出和错误信息。 |
| PRD-FR-031 | 系统可以为运行中的档案暴露本机 CDP 调试地址；默认只绑定回环地址，不得默认暴露到容器外或局域网。 |

### 9.5 运行形态

| 编号 | 需求 |
| --- | --- |
| PRD-FR-032 | macOS 桌面应用必须支持 Apple Silicon、macOS 13 及以上，使用有头模式启动内核，并通过系统钥匙串保护主密钥。 |
| PRD-FR-033 | Docker 服务必须提供 Web UI 和 HTTP/WebSocket 控制面，支持 `linux/amd64`，并以非 root 用户运行。 |
| PRD-FR-034 | Docker 有头模式必须使用 Xvfb 提供虚拟显示，使用 openbox 提供基本窗口管理；默认分辨率为 1920x1080x24，可通过环境变量配置。 |
| PRD-FR-035 | Docker 有头模式可以提供可选的 noVNC 查看入口；该入口必须有独立认证或一次性令牌，默认关闭。 |
| PRD-FR-036 | 无头模式必须在桌面与服务端都可用，但必须显式启用，并在 UI、API 和档案状态中标记降低保证。 |
| PRD-FR-037 | 系统不得把无头模式宣传为与有头模式等价的指纹保证；无头模式的启动响应和档案详情必须包含限制说明。 |

### 9.6 控制面与自动化

| 编号 | 需求 |
| --- | --- |
| PRD-FR-038 | 服务端控制面必须提供登录、会话管理、API Token 创建与撤销；Token 必须可限定档案读取、档案写入、运行时控制和查看器范围。首次启动必须生成高熵管理员密码或要求部署者提供，并强制首次登录后修改。 |
| PRD-FR-039 | 控制面必须提供版本化的 REST API 与 WebSocket 事件流，覆盖档案、代理、运行时、内核、健康检查和审计事件。 |
| PRD-FR-040 | 启动接口必须返回运行时标识、状态、CDP 地址（如启用）和中继端口；停止接口必须幂等。 |
| PRD-FR-041 | 服务端默认只在容器网络内监听部署端口，由部署者决定端口映射和 TLS 终止；所有写操作必须校验来源、会话和 CSRF 防护。 |
| PRD-FR-042 | 控制面必须提供健康检查和就绪检查，供容器编排与反向代理使用。 |
| PRD-FR-043 | API 必须使用统一错误结构，包含稳定错误码、可读消息和请求标识；错误不得泄露密码、令牌、Cookie 或完整启动参数中的敏感值。 |
| PRD-FR-044 | 控制面必须记录审计事件，包括登录、档案创建/删除、启动/停止、代理变更、Token 变更、内核切换和查看器开启。 |

### 9.7 导入导出与备份

| 编号 | 需求 |
| --- | --- |
| PRD-FR-045 | 用户可以导出档案配置为带 schema 版本的 JSON；默认不包含代理密码、Cookie 和浏览器数据。 |
| PRD-FR-046 | 系统必须支持带口令的加密导出，使用现代口令派生和认证加密；口令不得被持久化。 |
| PRD-FR-047 | 导入必须校验 schema、字段类型、文件大小、路径和代理地址；非法或不兼容数据必须拒绝并给出具体原因。 |
| PRD-FR-048 | 导入不得覆盖现有档案；冲突时必须生成新标识或要求用户显式选择。 |
| PRD-FR-049 | 系统必须提供数据目录备份与恢复说明，覆盖 SQLite、档案目录、内核目录和主密钥；恢复后必须能通过完整性检查。 |

### 9.8 内核管理与更新

| 编号 | 需求 |
| --- | --- |
| PRD-FR-050 | 系统必须随发布绑定经过校验的内核版本，并在首次使用前验证 SHA-256；校验失败必须拒绝启动。 |
| PRD-FR-051 | 系统必须为每个内核版本和平台维护能力清单，记录支持的开关、取值、派生特征和已知缺陷。 |
| PRD-FR-052 | 应用更新与内核更新必须分离；内核升级不得静默改变已有档案，运行中的档案不得被替换。 |
| PRD-FR-053 | 内核升级前必须执行准入测试并展示差异；用户显式迁移后必须重新校验指纹规格。 |
| PRD-FR-054 | 系统必须保留可回滚的上一内核版本，直到用户确认新版本稳定或达到配置的保留期限。 |

### 9.9 体验与可访问性

| 编号 | 需求 |
| --- | --- |
| PRD-FR-055 | Web UI 必须支持简体中文和英文，界面语言与档案语言、时区、代理地区相互独立。 |
| PRD-FR-056 | 关键操作必须有明确的加载、成功、失败和空状态；启动失败必须提供可复制的诊断信息。 |
| PRD-FR-057 | 危险操作必须二次确认，并在确认文案中说明数据影响，例如删除浏览器数据、禁用泄漏保护、开启无头模式。 |

## 11. 约束与依赖

| 约束 | 影响 |
| --- | --- |
| 内核固定为 fingerprint-chromium `148.0.7778.215` | 上游 150 在 canvas 伪装下存在渲染崩溃与站点加载失败；150 没有 macOS 构建；148 源码已公开。 |
| 上游不提供技术支持 | 缺陷只能通过版本准入、沙箱、功能降级或自建补丁分支处理。 |
| 上游源码延迟发布 | 新版本在源码公开前无法审计，不能作为安全敏感升级的默认选择。 |
| macOS 构建仅 ARM64 | 不支持 Intel Mac；Apple Silicon 是唯一 macOS 目标。 |
| Linux 构建仅 x86_64 | Docker 镜像为 `linux/amd64`；原生 ARM64 需自行编译内核。 |
| 代理认证不由内核支持 | 必须使用本地中继注入凭据。 |
| 显示属性不可任意伪造 | `screen.*`、`devicePixelRatio`、`colorDepth` 与窗口外框受宿主或 Xvfb 配置约束。 |
| 字体枚举受宿主字体集影响 | 跨系统画像可能泄漏宿主字体；主机对齐是默认策略。 |
| 无头模式指纹保证较弱 | 作为显式降级选项，不作为默认运行模式。 |
| CDP 没有认证 | 只能绑定回环地址；远程自动化需通过隧道或额外网关。 |
| Chromium 沙箱在容器中需要额外配置 | 默认要求验证沙箱状态；无沙箱运行必须显式授权并记录风险。 |
| 内核为 BSD-3-Clause | 分发时必须保留版权与许可声明，并链接上游源码。 |

## 12. 验收与发布门槛

### 12.1 必过场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| PRD-ACC-001 | macOS 首次部署 | 安装、内核校验、创建档案、启动有头浏览器、访问探针页、停止并再次启动成功。 |
| PRD-ACC-002 | Docker 首次部署 | 非 root 容器启动、登录、创建档案、Xvfb 有头启动、Web UI 状态正确、数据卷重启后保留。 |
| PRD-ACC-003 | 指纹一致性 | 同一档案三次启动的探针哈希一致；不同档案的种子派生特征不同；平台、UA、UA-CH、语言、时区内部一致。 |
| PRD-ACC-004 | 代理与泄漏 | HTTP 与 SOCKS5 认证代理可用；DNS 无本地泄漏；WebRTC 无直连候选；中继停止后网络失败关闭；IPv6 无绕过。 |
| PRD-ACC-005 | 无头降级 | 无头档案可启动并被标记降低保证；UI 与 API 均显示限制；切换到有头模式后可重新验证。 |

| PRD-ACC-007 | 导入导出 | 明文与加密导出可导入；错误 schema、超长字段、路径穿越和非法代理被拒绝；密码不出现在导出中。 |

| PRD-ACC-010 | 发布物 | macOS 应用签名并公证；Docker 镜像可复现构建、带健康检查、通过漏洞扫描；许可与已知限制文档齐全。 |

### 12.2 发布门槛

- PRD-ACC-001 至 PRD-ACC-010 全部通过，或经产品负责人书面接受残余风险。

## 13. 风险与缓解

| 风险 | 证据 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 内核 150 在 canvas 读回时崩溃 | 上游 issue #94、#95、#104、#112：`getImageData`/`readPixels` 触发 SIGSEGV，x.com 加载失败，148 正常 | 高 | 固定 148；150 仅作为候选内核，必须通过准入测试后才可升级。 |
| 内核 148 存在 WebGL readPixels 越界访问报告 | 上游 issue #102：打包 16 位格式被按 RGBA8888 处理，渲染进程可触发堆越界读写 | 高 | 强制 Chromium 沙箱；容器禁止默认 `--no-sandbox`；限制不可信站点；跟踪上游修复并保留补丁分支预案。 |
| 字体与屏幕属性无法按画像伪造 | 上游 issue #105：屏幕与字体开关无效果；宿主字体仍可枚举 | 高 | 默认主机对齐；UI 显式提示；测试矩阵覆盖；不承诺跨系统字体一致。 |
| 无头模式暴露 Headless 特征 | 上游 README 仅声明替换 UA 中的 HeadlessChrome | 中 | 无头作为降级选项；默认 Xvfb 有头；文档和 API 标记。 |
| Docker 中 Chromium 沙箱配置困难 | 容器默认 seccomp/用户命名空间限制 | 高 | 提供受支持的 seccomp/启动配置；启动前验证沙箱状态；无沙箱必须显式开关并记录。 |
| Apple Silicon 运行 amd64 镜像性能下降 | 无原生 linux/arm64 内核 | 中 | 文档说明模拟运行；容量目标按 amd64 环境测量；原生 ARM64 作为后续项。 |
| 上游无技术支持且源码延迟 | 上游 README 明确说明 | 中 | 固定版本、能力清单、准入测试、保留回滚；不依赖最新版本。 |
| CreepJS 在 148 Windows 上卡住 | 上游 issue #108 | 中 | 使用自有探针为主、第三方站点为辅；不以单一站点作为发布门禁。 |
| 指纹噪声实现存在一致性问题 | 上游 issue #98、#99：子区域读回与完整读回不一致 | 中 | 探针覆盖子区域与完整读回；记录已知差异；不作为“完美一致”承诺。 |
| `navigator.deviceMemory` 返回 16/32 不常见 | 上游 issue #100 | 低 | 能力清单标注；探针记录；后续内核修复后重新评估。 |
| CDP 输入事件坐标可被检测 | 上游 issue #110 | 中 | 仅作为自动化接口；不承诺反检测；文档说明。 |
| 多账号使用触碰平台条款 | 产品性质 | 高 | 可接受使用政策；用户责任；不提供规避指导。 |
| 代理凭据或 Cookie 泄露 | 本地或容器被入侵 | 高 | 主密钥保护、文件权限、日志脱敏、卷加密建议、最小权限。 |
| 容器逃逸或内核漏洞 | 非 root、沙箱、依赖漏洞 | 高 | 非 root、只读根文件系统、丢弃能力、seccomp、镜像扫描、及时更新。 |

## 14. 合规与可接受使用

Snailfish 仅用于合法、授权的环境隔离、测试、隐私研究和多账号运营。用户必须遵守目标网站的服务条款、当地法律、数据保护要求和代理服务商条款。

禁止将产品用于欺诈、身份盗用、未经授权的访问、垃圾信息、规避执法、支付欺诈、未成年人伤害或其他违法活动。产品不提供代理、账号、验证码或身份材料，也不对用户使用产品造成的账号封禁、数据损失或法律责任负责。

产品文档和 UI 不得暗示产品可以隐藏真实身份或保证绕过检测。发现滥用或安全漏洞时，维护者可以限制分发、发布安全公告或终止支持。
