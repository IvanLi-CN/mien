# ADR-0006：显式指纹规格与种子派生模型

- 状态：已接受
- 决策范围：指纹字段、生成规则、能力校验与迁移语义

## 背景

fingerprint-chromium 通过 `--fingerprint=<seed>` 启用大部分指纹伪装，并由种子派生 canvas、音频、WebGL、设备内存、GPU 参数等特征；同时提供平台、平台版本、品牌、品牌版本、CPU 核心数、语言、时区、代理和选择性禁用开关。上游还存在一些被命令行接受但没有实际效果的参数，例如屏幕尺寸和字体列表；如果产品把这些参数暴露给用户，会造成“已设置但未生效”的错误预期。

产品需要同时满足可复现、内部一致、可迁移和诚实呈现限制。纯种子模型无法表达用户对平台、语言、时区、品牌和 CPU 的明确要求；完全显式模型又无法控制种子派生的 canvas、音频与 GPU 细节。

## 决策

- 指纹规格由“显式字段 + 种子派生”组成。显式字段包括平台、平台版本、品牌、品牌版本、CPU 核心数、语言、时区、窗口尺寸、伪装开关和 WebRTC 策略；种子决定未显式暴露的派生特征。
- 种子为 32 位非零整数，由密码学安全随机源生成，并在档案创建或复制时检查冲突。
- 默认预设与宿主操作系统一致；跨系统画像必须显式选择并标记降低保证。
- 屏幕尺寸、设备像素比、颜色深度、字体白名单不作为可伪造字段暴露；UI 只显示宿主实际值和限制说明。
- 不暴露自由格式的 User-Agent 或原始 UA-CH 覆盖。品牌和版本通过内核支持的参数表达，避免 UA、UA-CH 与内核实际版本矛盾。
- 所有字段必须通过当前内核能力清单校验；清单外的字段和取值拒绝保存或启动。
- 规格带 schema 版本；迁移保留未知字段或拒绝加载，不静默丢弃。内核版本变化后重新校验规格，并提示派生特征可能变化。
- 启动参数由类型化构建器确定性生成，使用参数数组，不经过 shell；相同规格生成相同 argv。
- 一致性规则至少覆盖：平台与 UA/UA-CH、品牌与平台、品牌版本与内核主版本、CPU 核心数合理性、语言与时区、代理地区建议、伪装开关与内核能力。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 纯种子 | 简单；派生特征自然一致 | 无法表达平台、语言、时区、品牌和 CPU 要求 | 不采用 |
| 完全显式，包括 canvas/音频噪声 | 控制最强 | 内核不提供逐项参数；容易产生内部矛盾 | 不采用 |
| 允许自由 UA/UA-CH | 灵活 | 与内核版本、Client Hints、平台矛盾；高维护成本 | 不采用 |
| 显式字段 + 种子派生 | 兼顾控制与一致性；可复现 | 部分特征不可细调；依赖能力清单 | 采用 |

## 后果

- 用户不能逐项调 canvas 噪声、音频噪声或 GPU 型号；这些由种子和内核决定。产品必须说明原因。
- 跨系统画像的字体与显示泄漏无法完全消除；默认主机对齐，跨系统作为高级选项。
- 能力清单成为产品与内核的契约；内核升级必须更新清单并重新跑一致性测试。
- 种子冲突检测和规格迁移是必要功能，不能只依赖随机概率。
- 指纹探针需要区分“显式字段”“种子派生字段”和“宿主绑定字段”，测试报告也按此分类。
