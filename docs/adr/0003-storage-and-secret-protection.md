# ADR-0003：SQLite 存储与字段级密钥保护

- 状态：已接受
- 决策范围：持久化、密钥来源、敏感字段加密与残余风险

## 背景

产品需要在单机和服务端容器中保存档案元数据、分组、标签、代理配置、API Token、内核与协议引擎清单、运行状态和审计事件。数据量不大，但要求事务一致、易备份、无需额外服务，并且不能把代理凭据（密码、UUID、私钥）或 Token 明文写入日志或数据库。浏览器档案目录包含 Cookie、LocalStorage 和站点数据，由 Chromium 自身管理，产品无法在不修改内核的前提下透明加密这些文件。

## 决策

- 使用 SQLite，开启 WAL、外键和显式迁移；数据库位于 `<data-root>/db/snailfish.db`。
- 代理凭据（密码、UUID、私钥）等敏感字段使用 AES-256-GCM 字段级认证加密；密文包含随机 nonce、版本号和关联数据，关联数据绑定记录标识与字段名。
- 主密钥来源：
  - macOS 桌面：32 字节主密钥存入系统登录钥匙串，应用启动时读取，不写入磁盘。
  - Docker：优先读取 `SNAILFISH_MASTER_KEY`；未提供时首次启动生成 `/data/secrets/master.key`，权限 0600，运行用户独占。
- API Token 使用高熵随机值，数据库只保存带服务端 pepper 的哈希；登录密码使用 Argon2id。
- 加密导出使用用户口令和 Argon2id 派生密钥，导出文件使用认证加密；口令不持久化。
- 浏览器档案目录不进行应用层加密。部署文档要求 macOS 全盘加密、Docker 数据卷所在磁盘加密，并限制数据目录权限为 0700。
- 主密钥丢失时不自动清空数据库；系统进入“密钥不可用”状态，要求恢复密钥或执行显式重置流程。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 明文 SQLite | 简单 | 密码与 Token 泄露风险不可接受 | 不采用 |
| 整库加密（SQLCipher） | 静态数据全覆盖 | 迁移、备份、密钥轮换复杂；浏览器目录仍不受保护 | 不采用 |
| 字段级加密 + 系统密钥 | 风险聚焦；实现简单；可审计 | 浏览器数据仍依赖磁盘加密 | 采用 |
| 全部放在系统钥匙串 | 单机安全 | 服务端无统一钥匙串；容量与可移植性差 | 不采用 |

## 后果

- 数据库泄露时代理凭据与 Token 不直接可用，但档案元数据、Cookie 目录和运行日志仍可能泄露。
- 主密钥轮换需要重新加密敏感字段；必须提供显式迁移与备份步骤。
- 服务端以环境变量提供密钥时，密钥可能出现在容器检查或编排配置中；文档要求使用 Secret 管理并限制读取权限。
- 日志、错误响应和审计元数据必须统一脱敏，避免在应用层重新泄露敏感值。
- 备份必须同时覆盖数据库、档案目录和主密钥；缺少主密钥的备份只能恢复非敏感元数据。
