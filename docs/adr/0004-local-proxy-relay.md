# ADR-0004：每档案本地代理中继

- 状态：被 [ADR-0007](0007-protocol-engine-forward-proxy.md) 取代
- 决策范围：代理认证、DNS 解析、泄漏防护与失败行为

> 本决策的本地中继不再作为数据面。当前链路是 `ADR-0004 → ADR-0007 → ADR-0009`：VLESS、VMess、Shadowsocks、Trojan、Hysteria2 等协议由 ADR-0009 的单实例 Xray 共享引擎处理；ADR-0007 的 sing-box 方案也已被取代。本文件保留为历史背景，当前契约以 `docs/specs/proxy-gateway/SPEC.md` 为准。

## 背景

fingerprint-chromium 的 `--proxy-server` 支持 HTTP、HTTPS 与 SOCKS 代理，但不支持在启动参数中携带用户名密码。商业代理通常要求认证；如果直接把凭据放进 URL 或启动参数，会出现在进程列表、日志和崩溃转储中。另一个问题是 DNS：本机解析目标域名会泄露访问意图，WebRTC 与 IPv6 也可能绕过代理。产品需要一种不修改内核、能注入认证并保证失败关闭的方案。

## 决策

- 每个运行档案启动一个独占的本地中继，绑定 `127.0.0.1` 的临时端口，生命周期与浏览器进程绑定。
- 内核只接收 `--proxy-server=http://127.0.0.1:<relay_port>`，不接触上游凭据。
- 中继接受浏览器的 HTTP 代理请求，包括 `CONNECT` 与绝对 URI 请求，并按配置转发到上游 HTTP、HTTPS 或 SOCKS5 代理。
- 上游认证由中继注入：HTTP 使用 `Proxy-Authorization`，SOCKS5 使用用户名密码握手；凭据只存在于中继内存和加密数据库。
- 对上游使用远程 DNS：HTTP `CONNECT` 发送域名，SOCKS5 使用域名地址类型，不在本机解析目标主机。
- 中继失败或被关闭时，浏览器不得回退直连；内核的代理配置在启动时固定，无法自动切换。
- 默认向内核传入 `--disable-non-proxied-udp`，阻止 WebRTC 非代理 UDP；禁用需要高级确认和审计。
- 默认禁用 DNS-over-HTTPS 绕过，并在测试中验证；无法保证的部署必须在 UI 显示限制。
- IPv6 代理与直连风险纳入启动前检查；不能代理 IPv6 时阻止或明确告警，不允许静默直连。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 代理 URL 携带凭据 | 无额外进程 | 凭据出现在进程列表与日志；URL 编码兼容性差 | 不采用 |
| Chromium 扩展处理认证 | 不需要中继 | 扩展增加指纹面；难以覆盖所有请求；生命周期复杂 | 不采用 |
| CDP `Fetch.authRequired` | 内核原生能力 | 仅对已连接 CDP 的会话生效；非自动化场景不可用 | 不采用 |
| 修改内核支持代理认证 | 体验最好 | 需要维护 Chromium 分支；升级成本高 | 不采用 |
| 本地中继注入认证 | 内核无感；集中做 DNS/泄漏控制；可观测 | 增加进程与端口；用户态转发有性能成本 | 采用 |

## 后果

- 中继成为每个运行档案的关键路径；必须处理并发连接、超时、上游失败、半关闭和进程退出。
- 本机同用户进程理论上可以使用回环中继端口消耗上游代理额度；中继只绑定回环、随机端口、短生命周期，并在容器中通过网络隔离降低风险。该残余风险写入安全文档。
- 代理认证失败、上游不可达和 DNS 失败必须返回明确错误，并在 UI 中可诊断。
- 不代理 UDP；依赖 WebRTC 禁用来避免泄漏。需要 UDP 的站点可能不可用。
- 代理延迟增加一次用户态转发；容量测试必须覆盖高并发连接和大响应体。
- 中继不记录完整 URL 或凭据；只记录连接结果、耗时和脱敏目标。
